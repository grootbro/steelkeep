# Snapshot downloads

Downloads expose database contents. The separate `backup:download` permission is required for the descriptor and the archive; a `read` token cannot download data. Existing agent and installation-scoped browser grants are not upgraded. A verified owner account retains full installation permissions. Named agent tokens can explicitly receive this grant and remain subject to expiry and revocation.

The snapshot action uses the browser's native attachment download. `GET /api/v1/backups/:id/download-info` and MCP `get_backup_download` return a filename, recorded size/SHA-256 and relative path. Retrieve that path from the same installation with the same session or Authorization header. No storage credentials, bearer URL or presigned S3 URL are returned. MCP carries metadata, not binary archive contents.

The archive stream uses the saved S3 connection and immutable object key. The complete size and SHA-256 are checked while streaming; the final block is withheld until those checks agree. A mismatch ends the stream before its final block is delivered, leaving fewer bytes than the recorded size. On the pinned Bun 1.4.0 runtime asynchronous responses use HTTP chunked framing even when the service sets Content-Length; a real-socket probe confirmed that stream errors abort that transfer. The descriptor remains the authoritative expected size. Discard partial files and independently compare the saved file's SHA-256 before use. Matching bytes do not establish restore validation.

Only active retained objects can be downloaded. A retention lock does not prevent a read; queued, deleting, held and deleted objects cannot begin a download. A storage failure never clears cleanup or recovery protection. Starting a download does not pin an object against retention, and an interrupted read can be restarted only while the object remains available.

There are no temporary archive copies on the API disk. Streams use backpressure and at most one 64 KiB final block in addition to the upstream transport buffer. Each API process admits at most two concurrent downloads. Storage headers have a 10-second deadline; transfers stop after 15 minutes or credential expiry. Closing the client releases the upstream stream/client and admission slot. Full archives only: Range/resume is unsupported in this release. Archives retain their native format; this endpoint does not add encryption or transform their contents.

The audit records `backup.download.started` and, after complete byte verification, `backup.download.verified`. Verification is not a client-delivery receipt. Neither event includes archive contents or storage credentials.

The implementation uses the existing AWS SDK GetObject operation and native Response streaming, following [AWS GetObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html), [Elysia handlers](https://elysiajs.com/essential/handler) and [Bun request timeouts](https://bun.com/docs/runtime/http/server#server-timeout-request-seconds). The isolated server checkpoint passed a real fresh RustFS/AWS-SDK download test: 53 assertions, six GetObject calls and 3,145,845 HTTP bytes independently SHA-256 matched. A same-size corrupt object produced an incomplete rejected HTTP stream; read-only access was denied, explicitly scoped access worked and token revocation stopped subsequent access. Direct route WebStream cancellation against the real SDK NodeReadable confirmed upstream destruction, slot release and source closure; this is distinct from an actual browser disconnect proof. Fixture databases/buckets were removed with ownership guards, and the stand's PostgreSQL/RustFS were stopped with volumes/evidence retained.

The download proof snapshot is `ab62e19bd27809014143b9604af533c1f60bd5c5651633150905133c84290f86`. Its product modules are byte-identical to the earlier full TypeScript check; the intervening overlays changed two CSS files, optional UID guards in proof scripts and the test's observed Bun framing assertion. Acceptance TypeScript, 84 default tests / 693 assertions and the plan metadata proof passed in the same documented chain. No native backup was created by the download test, and no existing object or production data was accessed.

## Actual HTTP disconnect and expiry

A separate lifecycle test on committed product `570f121` plus only `tests/artifact-download-lifecycle.integration.test.ts` passed TSC and 27 assertions in6.11s. It used a controlled loopback S3 GetObject protocol fixture, the real AWS SDK NodeReadable and actual Bun/node:http client sockets. Destroying a client after32,768bytes closed the upstream at65,536 of8,388,608bytes. Expiry without client cancellation closed it at2,064,384bytes (2,031,616 delivered). Both aborted the signal/SDK stream before EOF, preserved the sibling download, returned429 for a third stream and admitted a replacement after release; expired credentials then returned401 and no verification-complete audit was written.
