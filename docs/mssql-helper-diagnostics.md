# SQL Server helper diagnostics

The Linux x64 DacFx helper reports a handled failure as a JSON error envelope with `MSSQL_HELPER_FAILED` and an allowlisted operation stage. Manifest stages distinguish permissions, portable-feature guards, table/column catalogs, schema hashing, row digests and identity/sequence values. It never serializes exception messages, stack traces, driver diagnostics, SQL or credentials. The adapter rejects an error envelope; a zero process exit does not establish export/import success. Crashes, resource limits, cancellation and timeouts retain the native runner's existing refusal behavior.

`inspect`, identity/catalog inspection and manifest generation perform reads only. An import error does not establish its server-side outcome: keep the owning restore job and target reservation protected, with no automatic replay.

The initial isolated SQL Server proof failed before export because the lean image ran UID 10001 without a corresponding operating-system user entry. A controlled read-only comparison kept the same UID, capabilities, filesystem and helper: connection opening failed without that entry and succeeded with a runner-only read-only `/etc/passwd` mount adding it. The host and image user databases were unchanged. The lean proof Dockerfile now registers `steelkeep` UID/GID 10001. The ordinary engine base already registers that account, so the optional MSSQL extension verifies it instead of adding a duplicate.

SQL Server 2022 includes internal ledger columns in `sys.columns`; portable application-schema validation now restricts column feature checks to user tables. It still refuses unsupported features on user tables. Built-in R/Python external-language entries are ignored by both TypeScript target-emptiness inspection and C# catalog validation, using the actual `sys.external_languages.language` column. Microsoft documents these as [reserved language names](https://learn.microsoft.com/en-us/sql/relational-databases/system-catalog-views/sys-external-languages-transact-sql?view=sql-server-ver17); other external languages remain a refusal.

[Large `FOR JSON` results can span multiple rows](https://learn.microsoft.com/en-us/sql/relational-databases/json/format-query-results-as-json-with-for-json-sql-server?view=sql-server-ver17). The helper's text reader now concatenates all result rows before schema hashing and refuses more than 2 Mi characters. The existing complete serialized-result byte limit remains in force. Reading only the first scalar could otherwise omit later catalog definitions.

The corrected source passed actual read-only manifest generation against the retained synthetic READ_ONLY SQL Server 2022 source with DacFx 170.5.96.0. All 19 separately inspected feature guards returned zero. A separate compiled probe exercised the actual private text-reader method: a 5,000-character JSON value was fully reassembled and a 2,200,000-character result was refused. The probe source is `tests/mssql-long-json.probe.cs`; it accepts private JSON only on stdin and refuses any host/login/database outside the exact synthetic source. Runtime checks asserted UID 10001, no effective capabilities, no new privileges and a read-only root filesystem. Parser tests passed 2 tests / 54 assertions; project typecheck and diff checks passed.

The final helper was compiled with the official Linux x64 SDK's Roslyn compiler alone, the stand's existing .NET 10.0.14 runtime and existing pinned published dependencies. The compiler container had no network, no secrets, a read-only root, UID 10001, 512 MiB memory and 0.5 CPU. No SDK image, NuGet packages or application image rebuild was needed. The compiler's implementation-assembly references produced CS1701 warnings for SqlClient's .NET 9 System.Data.Common reference against .NET 10; the actual runtime probes above passed. All temporary SDK/compiler directories and archives were removed after verification. This is helper/runtime evidence, not rebuilt immutable-image acceptance.

The original failed backup and original proof result remain intact. The read-only investigation performed no export/import, reseed or metadata reset. All temporary SDK/compiler files and compressed compiler caches were removed; the small compiled helper, probe and evidence remain.

A later root-authorized single native attempt (`attempt-2-nss-catalog-json`) successfully exported a BACPAC and published an immutable S3 artifact. Independent full GET verified 4,636 bytes and SHA-256 `5b3225d2539b8a98991a518b54546457baf78d6b9f107c5cbdf71090889c347d`. Backup job: `f099a768-662a-41cc-abb9-144795910c75`; artifact: `e7316e24-50d8-494a-b4d4-d80bfb48b843`.

Import into the separately provisioned restricted destination refused with `MSSQL_HELPER_IMPORT`. Restore job `c715a9db-9094-4a2a-8036-2e2288be48fc` is **interrupted**, and target `38862a02-7954-4988-805b-cc45df7b8ec5` / `recovery_mssql_f768c9613ff4` remains protected by that job's persisted target reservation. The native test group failed after 98 assertions; this is backup/publication evidence, not successful SQL Server recovery. No retry was made.

Independent read-only inspection after the refusal found the held target online, in multi-user mode, with zero user tables and zero user objects. The source principal and its owner-role membership were absent from the target. Source remained READ_ONLY with two tables, two project rows and three entry rows. An empty visible catalog does not establish that import never wrote or make the held target reusable. Exact DacFx failure detail was suppressed by the previous helper's stage-only protocol and remains unconfirmed. Offline inspection of the independently verified BACPAC found 35 model elements, including one SqlLogin, one SqlUser, one SqlRoleMembership and three SqlPermissionStatement elements; the source fixture principal is present. The model has two SqlTable elements, uses the SQL 160 provider and does not set ReadOnly=true. These facts support investigating server-principal deployment under the limited target role, but they do not establish the exact thrown error. A usable application-data restore must also prevent silent restoration of source login/user/role mappings onto a different target; do not solve this by granting broader server privileges. A bounded next investigation should inspect the captured BACPAC model and generate read-only deployment diagnostics to distinguish existing-target semantics, limited-role requirements and principal restoration; it must not replay import or change permissions on the held destination.

API, worker and SQL fixture were stopped after the terminal attempt and read-only inspection. Metadata, S3 archive, all SQL databases/logins, original proof result, separate attempt result and failed-group log were preserved. The native disk monitor sampled a minimum of 8,866,279,424 available bytes; its 8.25 GiB soft stop was not triggered. The backend remained the frozen `680c7ad` image plus individual read-only mounts for the corrected helper/adapter/NSS account and the root's explicit continuation guard/harness. This does not qualify unrelated later platform changes or a rebuilt immutable image.
